# ADR 0006: Physics: Liljegren WBGT, guarded ISO 7933 PHS, in-house NIOSH RAL/REL, TWL ported from an MIT reference

- **Status:** Accepted (Ali, 2026-11-11), with one correction to the brief (TWL, below)
- **Evidence:** `docs/research/2026-11-11-backend-ml-stack.md` §1 findings 2, 4, 5, §6.3-6.6; `docs/research/2026-11-11-claims-verification.md` §2, §3, §6; `D:\dev\future-health-challenge\scripts\audit_wbgt.py`

## Context
Abu Dhabi's code (ADOSH-SF CoP 11.0 v4.0) keys controls to TWL zones; NIOSH 2016 keys limits to WBGT and metabolic rate; PHS predicts strain and duration limits. Each tool has a defect or gap that shapes the code.

## Decision
- **WBGT:** `thermofeel` 2.3.0 `calculate_wbgt_liljegren` (returns K), with solar geometry **ported verbatim from `audit_wbgt.py`** (`cos_zenith`, `mean_cos_zenith_prev_hour`; 5.0e-5 max |Δcos z| vs pvlib). Open-Meteo radiation is the mean over the preceding hour. Never `calculate_wbgt_simple`. Elements with non-finite inputs, incoherent radiation (radiation while the sun is below the horizon all hour), non-convergence, or a result outside [T-30, T+10] °C become NaN with a reason code.
- **PHS (ISO 7933:2023):** `pythermalcomfort` 4.8.1 `phs`, behind (1) input validation (finite; applicability window 15<tdb<50, 0<tr-tdb<60, 0<v<3, 0.1<clo<1, 0.96-4.3 met; positive height/weight) and (2) a **hard timeout in a separate process** (a numba kernel cannot be interrupted from a thread; NaN input hangs forever, issues #524/#523, reproduced on 4.8.1). Outputs with rectal temperature outside 36-42 °C are rejected.
- **NIOSH RAL/REL:** in-house: REL = 56.7 - 11.5·log10(M), RAL = 59.9 - 14.1·log10(M), M in whole-body watts (NIOSH 2016 ch. 8.1, verbatim). Test vectors: M=180 W → REL 30.76, RAL 28.10; 300 W → 28.21, 24.97; 415 W → 26.59, 22.99. Clothing adjustments from **NIOSH Table 3-2** (ACGIH-derived), labelled as such.
- **TWL:** in-house **port of `vorpalvorpal/meteoHazard` `solve_twl_single`** (Brake & Bates 2002 Appendix 1, three-zone evaporation), pinned to commit `5633d5719225d15d84f2608189e2b3d654dba73d`, labelled **"aligned with ADOSH TWL zones"**, never "ADOSH-compliant". **ADOSH zones: ≥140 W/m² Low risk (unrestricted), 115-140 Medium (cautionary), <115 High** (Technical Guideline Table 1, printed as "140 - 220 <", "115 - 140", "< 115"; the boundary convention is ours: exactly 140 → Low, exactly 115 → Medium). Test vectors: **Miller & Bates 2007 Table 2** (11 chamber sessions).

## Correction to the brief: an open TWL implementation exists
The stack doc (finding 5) searched Python code, PyPI and GitHub code search and found none. The claims doc (§3) found the R package above, which the stack doc's searches did not cover. I checked it on 2026-11-11: `DESCRIPTION` says `License: MIT + file LICENSE`; `LICENSE` is the standard CRAN MIT stub (`YEAR: 2026`, `COPYRIGHT HOLDER: TWL authors`); last commit 2026-09-29; single maintainer; its DOI is wrong (`...317070947`; the paper is `10.1080/104732202753438261`). Porting with the MIT notice and attribution is permitted. The B1 plan keeps a licence re-verification step before the port. If the licence changes, implement from the published equations instead.

## Consequences
- **Measured bias, safety-relevant:** an independent scratch port (2026-11-11, WMO psychrometer conversion from the published wet-bulb values, MRT = dry bulb, 0.12 clo, vapour permeability 0.45, 101.3 kPa) reads **+3.9 to +7.0 W/m² (mean +6.2) above** the 11 published values; the claims doc measured +5.7 mean / 6.5 max. A higher TWL is **less protective**, and zone edges are 25 W/m² apart. **B3 must decide** how to handle readings within this band of 115 and 140 (recommendation: zone on TWL minus 7 W/m² and say so).
- The reference code also caps TWL at 115 W/m² when dry bulb > 44 °C or natural wet bulb > 32 °C ("withdrawal limits") and clamps to [60, 380]. The primary source of the two caps is not verified. B1 ports them as a separate function; **B3 decides** whether to apply them (dry bulb above 44 °C is common in UAE summer afternoons, so this choice moves many hours into the High zone).
- TWL needs mean radiant temperature (from radiation, via thermofeel's MRT routine in B3) and body-level wind (10 m wind × ln(1/0.01)/ln(10/0.01) ≈ 0.667; clamp 0.2-4.0 m/s).
- PHS returns NaN outside its window, including heavy work above 250 W/m² and heavy PPE; about 19.6% NaN even inside nominal ranges (cause not investigated). PHS is therefore advisory; NIOSH and TWL drive levels when PHS is unavailable.
- No published Liljegren test vector was located; WBGT correctness rests on port fidelity (golden values from the FHC functions), the pvlib solar oracle and physical properties.
- Every number and table here is cited in the model card and the technical document.

## Amendments
- **2026-11-12 (B1 as built, decision text unchanged):** what Tasks 5-6 and 12-14 showed. Evidence: B1 rulings 9, 12, 21; `backend/src/stellar_blaze/domain/physics/` (`wbgt.py`, `phs.py`, `twl.py`, `niosh.py`), `adapters/compute/phs_process.py`, `backend/THIRD_PARTY_NOTICES.md`; commits `f21b0ab` and `5e5fdd0` (Task 6), `973d5f0` (Task 12), `287dc04` (Task 13), `eca0477` and `5a38284` (Task 14), `5f00cbe` (final wave). SHAs are commits on branch `feat/b1-backend-foundation` (HEAD `5f00cbe`, not yet merged; a squash merge changes them, so the paths named are the lasting evidence). Rulings are numbered as in the B1 controller's `b1-summary.md`, which is deleted after the merge.
  1. **WBGT guard.** Negative `sw` or `direct` radiation is now `INCOHERENT_RADIATION` (reject code 2), because it is physically impossible and needs no threshold (ruling 9). The existing rule (`sw` above 10 W/m² while the mean cosine of the zenith over the preceding hour is 0) is unchanged; its 10 W/m² is an engineering threshold with no source (the B1 plan chose it), and the module says so. **Known gap, parked:** an hour that is partly sunlit (mean cosine above 0, mid-point cosine clipped to 0) accepts any shortwave: at OMAA, label 2025-07-15T01:50 UTC, `sw` of 100, 300 and 1000 W/m² give 29.4, 30.8 and 35.8 °C with reject 0. A ceiling needs coefficients derived from data and none was guessed; the Task 11 data can supply them (parking-lot row). **Cost of being wrong:** a mislabelled twilight hour yields a bounded (inside the [T-30, T+10] band) but wrong WBGT. Verified: the port is bit-identical to the FHC functions (golden atol 1e-9) and agrees with the pvlib oracle; on the gold dataset no forecast-side WBGT element was rejected.
  2. **PHS: the unexplained 19.6% NaN is explained.** Consequences says about 19.6% of inputs inside the nominal ranges return NaN, "cause not investigated". The cause is the kernel's own water-vapor-pressure limit, 0.5 ≤ p_a ≤ 4.5 kPa (ISO 7933 Annex A, Table A.1, 2023 edition): 38 °C at 70% relative humidity is 4.64 kPa, an ordinary Gulf summer reading. `validate_phs_inputs` now includes it, so an accepted input is never answered NaN for being out of range. The metabolic window is checked in W/m² at the kernel's own 58.15 W/m² per met (56-250 W/m²): "0.96 to 4.3 met" is a rounding, and the kernel returns NaN exactly at those two values. A zero `height` returns `t_re` 0.0 or raises `SystemError`; every one of the eight numeric inputs hangs the kernel when non-finite (reproduced). The body-size window is unsourced (`height_m = 0.001` passes; parking-lot row), and the worker starts lazily with no public `PhsRunner.start()` (worst-case first call about 70 s; parking-lot row). The hang is cut in about 10 s by the process timeout (`execute_unvalidated` is the public entry the hang test uses, ruling 12). The numba cache is baked into the image: a warm start takes 3.3-4.2 s against 13.8-15.3 s cold.
  3. **PHS output guard.** "Outputs with rectal temperature outside 36-42 °C are rejected" keeps its rejection and splits its reason: below 36 °C `implausible_output`, above 42 °C `exceeds_model_range`, which a consumer must treat as the most severe band and never as missing data. See [ADR 0039](0039-phs-exceeds-model-range-is-the-most-severe-band.md) (ruling 21): 154 of 3,249 validator-accepted nominal inputs (4.7%) land above 42 °C.
  4. **TWL.** The licence re-verification passed (MIT plus the CRAN stub; the notice is reproduced in `THIRD_PARTY_NOTICES.md`, which now ships in the image). The in-repo test measures the port against Miller and Bates 2007 Table 2 at +3.88 to +6.96 W/m² (mean +6.24), matching the +3.9 to +7.0 and +6.2 above. New evidence on the recommended flat "TWL minus 7": it fits the humid chamber data, but the zone-edge rows of Brake and Bates 2002 Table 1 (a 62-row table, transcribed in the test) read −2.8 to +2.2 W/m² against the published values (mean +0.03), and the driest rows read up to 13 W/m² below them (the protective direction). A flat margin is therefore calibrated on one dataset; B3 should choose it with that in view (it is the tunable `twl_margin_w_m2`, ADR 0010, default 0 in `ae-heat-0.1`). `apply_withdrawal_limits` now takes `limits` with no default, built from the ruleset's `[twl_withdrawal]` (`enabled = false` in `ae-heat-0.1`); the dataclass defaults stay only so a golden test pins the seed ruleset to the reference's numbers. The caps' primary source is still unverified. `twl_w_m2_array` raises for the whole batch on one impossible element (WBGT instead returns a reason code per element), so a B3 caller validates first; at wind 0 the floor of 60 W/m² applies, undocumented upstream. **Unverified data (Ali's choice):** neither Miller and Bates Table 2 nor the Brake and Bates Table 1 transcription was checked against the papers; the review verified the port against the reference code.
  5. **NIOSH.** The three published vectors (180, 300, 415 W) pass; `effective_wbgt_c` rejects negative adjustments; the Table 3-2 values (0, 0, 3, 0.5, 1, 11) live in the ruleset (ADR 0009).
