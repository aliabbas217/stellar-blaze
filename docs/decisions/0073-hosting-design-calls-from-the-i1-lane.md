## Decisions
1. **The api is not public.** On Azure it has internal ingress and `web` calls it over the environment's internal FQDN; on Render it is a private service. The web BFF holds the demo token and the per-client and global limits (ADR 0062), so a public api would let a caller skip both. The deploy gate and the smoke test never call the api over HTTP: they gate on the revision's own state (`latestReady`, image, provisioned, running, healthy, replicas) and on the BFF routes. `--forwarded-allow-ips "*"` stays in the api image only because the api is private and its limits are per token; `TRUSTED_PROXY_HOPS` is 1 (documented for Container Apps; on Render the proxy count is undocumented, so 1 fails safe, and the forged-header smoke check on the public URL is the proof).
2. **The deploy is two-phase and migrate-first:** phase 1 (environment, Postgres, the migrate job), the migration (`sb-jobs db upgrade`, `site load`, `alert_dispatch_interval_minutes = 1`, idempotent), then phase 2 (the apps). A real deploy with no migrate job fails; it is never skipped silently. The deploy ends with restart, a demo reset, the smoke test and a final reset, because the replay window starts at the first `site load` (ADR 0034 amendment of 2026-11-15, second entry).
3. **A local deploy path in native PowerShell** (`infra/scripts/deploy-local.ps1`: Doctor, InitSecrets, Bootstrap, Validate, Deploy, Warm, Cool, ResetDemo, Status, Teardown printing only) is the primary way Ali deploys. GitHub Actions is optional. The reason is a Windows one: Git Bash rewrites `/subscriptions/...` arguments and `az.cmd` output carries `\r`, which only show against a real `az`. Both paths share one contract. Secrets for the local path live in `%LOCALAPPDATA%\stellar-blaze-i1\secrets.json`, outside the repository and never printed.
4. **A production rehearsal replaces LocalStack.** `infra/local/rehearse.sh` runs Postgres with TLS from a run-time CA and a TLS-only HBA, migrate then `site load`, api, the alerts worker, web and an nginx that appends `X-Forwarded-For` like the Container Apps ingress, then the smoke test and the negative checks (plaintext refused, wrong CA, wrong host name and missing root fail closed). LocalStack for Azure was researched and rejected because it does not cover the risky parts of the Bicep (ADR 0072's research; `what-if` not implemented, federated credentials and budgets missing, no cron triggers, Postgres demo on `sslmode=require`).
5. **The Render fallback keeps ADR 0042 with no exception.** Managed Postgres is not used (internal connections do not support `verify-ca` or `verify-full`); the fallback runs its own Postgres as a private service with a CA we generate, and `ssl=require` is never shipped. If a verifying connection cannot be had, the Render files stay out of the deploy path and the last resort is the local stack plus the video. It was never applied, so its UNVERIFIED list stands.
6. **Burstable B1ms Postgres** is documented by Microsoft as "not recommended for production workloads" and without 24/7 support; acceptable for a demo, stated in the runbook. `ssl_min_protocol_version` stays at the default (setting TLSv1.3 would add an untested failure mode). The first `job-migrate` under `verify-full` against Azure is the end-to-end proof of ADR 0042 and nothing offline can show it.
7. **The template checker is large on purpose** (`template_checks.py`, about 1,400 lines): `bicep snapshot` leaves every expression that touches a secure parameter unevaluated, so the checker evaluates the compiled ARM expressions itself, mutation-tested, to assert the review-focus invariants offline. The maintenance cost is accepted.
8. **Alerts stays an always-on loop** (ADR 0072 amendment: the one-minute job was measured and rejected).

## Parked (index only; the table with reasons is in the plan-delta file, section 6)
A single small VM (about USD 39 a month running, 6.5 deallocated; the architect decides if the Environment Management Hour meter appears or Azure is blocked); a one-minute alerts job (revisit when Container Apps has a concurrency policy or a dispatch takes under about 30 s at 0.25 vCPU); Key Vault references, Entra database auth, VNet and private endpoints, a managed OpenTelemetry agent, a custom domain, PR-time what-if (stage 2); pinning the `containerapp` extension; a Windows CI job for the Pester suites; `budgetMonth` format validation; verification of the Render fallback.

## Consequences
- **Cost of being wrong:** every real `az` output shape, AcrPull propagation, the first `verify-full` against Microsoft's real chain, Node trusting the certificate on the internal FQDN, whether the ingress holds a request during scale-from-zero, and ARM's handling of the budget and secure-object details are unverified until the first deploy. The runbook's order (Validate, an optional placeholder deploy, then the real deploy) is designed to surface each early; a failure costs time, not data.
- A private api means a failure of the web to reach it is invisible from outside; the gates and smoke check on the BFF routes are the detector.
