## 4. B2: ML corrector and evaluation report (13-14 Nov), to be planned when B1 lands

- Features from the gold dataset (ADR 0005): raw forecast variables per model (IFS, GFS), lead, hour of day, day of year, station and cell elevation, elevation difference, recent observed bias (lagged by at least the lead, never leaking the target).
- Baselines: raw IFS / GFS / AIFS; additive bias correction; linear MOS (ADR 0007).
- LightGBM quantile grid (19 levels), CQR per lead x hour band on time-blocked calibration windows; WBGT uncertainty two ways (joint samples vs direct).
- Evaluation report `docs/research/2026-11-14-evaluation-report.md`: regimes (a), (b), (c) reported separately; 2026 as the final test; headline leads 1-3; MAE/RMSE, CRPS (19-level grid), pinball, interval score, coverage, PIT; daytime 06-14 UTC separately; per-station table; IFS vs AIFS vs GFS raw comparison 2025-2026 (must-have, plan E5).
- **Training hyperparameters (ADR 0010 class a):** in `backend/training/configs/<name>.toml`, validated by a frozen `extra="forbid"` `TrainingConfig` (LightGBM params, the 19-level grid, CQR strata and hour-band edges, calibration windows, feature set). `sb-jobs train --config <path>` is the only entry point; no CLI hyperparameter overrides; `--release` refuses a dirty tree. A training run is not a deployment.
- Artefacts and `model_card.md` (ADR 0007), laid out per ADR 0009 §3 as amended by ADR 0010: `backend/models/corrector-<yyyymmdd>-<gitsha7>-<cfg6>/manifest.json` (`cfg6` = first 6 hex of the training config's SHA-256) with per-file SHA-256, `gold_manifest_sha256`, `training_config_path`, `training_config_sha256`, `calibrated_pairs` (the symmetric pairs with CQR offsets) and per-regime metrics. The image keeps **every released model id**; switching or rolling back = a runtime config activation of `model_id` (validated, preloaded and warmed, then swapped; no new revision). A newly trained model still needs an image build. The `calibration_pair` tunable is validated against `calibrated_pairs`. If a booster file exceeds the 500 KB pre-commit limit, raise it with a scoped exclude for `backend/models/` and say so (no LFS for the demo).
- Stretch: AIFS-feature corrector; adaptive conformal arm; DRN comparator.

## 5. B3: risk, planner, governance, API (14-16 Nov), to be planned when B2 lands

- **Task 0 (14 Nov, before anything else):** OpenAPI v1 schema draft: routes, request/response models, problem types; merged so F2 can generate types from the committed `backend/openapi/v1.json`. On merge, the CI oasdiff step gains `--fail-on ERR` (v1 frozen: additive only; breaking = `/api/v2`, ADR 0009 §5).
- **Ruleset `ae-heat-2026.1` (ADR 0009 §1)**, released with `supersedes = ["ae-heat-0.1"]`, lock hash and golden file: ADOSH TWL zones plus the decided bias margin and the withdrawal-limit decision (ADR 0006), the 4-level probability bands, the NIOSH acclimatization schedule, the midday-ban window (dated, with exempt categories and cited MoHRE source), work-hour and break limits, k-suppression, planner soft-cost weights, and the action codes / template ids. Schema sections are added additively. Every code needs an `en` key in `frontend/messages/en.json` (backend unit test). `GET /api/v1/risk-policy` is a projection of the active ruleset **plus the active tunables** (ADR 0010); `version` = ruleset id, and `config_version` = the active config version id.
- **Tunables with reviewed ranges (ADR 0010 class b), in `ae-heat-2026.1` `[tunables]`** (each with `default`, `min`, `max`, `safer`, `source`; the less-protective end of each range is pinned by the golden file): `twl_margin_w_m2` (default = the ADR 0006 decision), the four probability-band thresholds, `alert_lead_hours`, `deescalation_dwell_minutes` (only delays de-escalation; escalation immediate, a hypothesis property test), the planner soft-cost weights, `calibration_pair` (validated against the model manifest), and `k_suppression` (min = 5, the privacy floor). `Tunables`, `EffectiveParams` and `RuntimeFlags` gain matching fields additively. Live flags: `compliance_drafter_enabled` (kill switch, default false) and `planner_full_constraints`; each is added with the code it gates. Every new floor field carries a `Floor` comparator (B1 Task 7A test).
- **Config admin API (ADR 0010 §3-4):** `GET /api/v1/config/active`, `GET /api/v1/config/versions/{id}`, `GET /api/v1/config/activations` (public, read-only; no secrets in the config); `POST /api/v1/admin/config/versions`, `POST /api/v1/admin/config/activations` (`{version_id, expected_previous_activation_id, reason}`), `POST /api/v1/admin/config/rollback`, all with `Authorization: Bearer`, where the token is mapped to an actor through `SB_ADMIN_TOKENS` (sha256 + `hmac.compare_digest`). Problems: 401/403 `unauthorized`, 409 `stale-activation`, 422 `config-invalid` with a `violations` member. Built on B1 Task 7B's `ConfigService`; regenerate `openapi/v1.json`.
- **Governance audit events (ADR 0010 §4.5):** `config.version_created`, `config.activated`, `config.rollback`, `config.rejected`, `config.auth_failed` go to the append-only audit table in the same transaction as the activation row. B3 extends the Postgres `RuntimeConfigStore` adapter to write both.
- **LLM routing (ADR 0010 §8), only for the kept compliance-report drafter:** `LlmInput[NonPersonal]` built from k-suppressed aggregates only; a route catalog from env; `llm_routes` in `RuntimeConfig`; fail closed; a PII pre-check; the test that a `Personal` payload cannot reach the managed adapter.
- **Audit columns (ADR 0009 §1, ADR 0010 §3):** every decision and alert table carries `ruleset_id text NOT NULL`, `ruleset_sha256 char(64) NOT NULL`, `model_id text NULL`, **`config_version_id bigint NOT NULL` (FK `config_version`) and `config_sha256 char(64) NOT NULL`**, and decision-carrying responses expose `policy_version` and `config_version`. `job-refresh` reads the active version once per run and records it in `job_run.params` and on every alert row. Migrations follow expand/contract (old revision keeps serving while `job-migrate` has already run).
- `composition.FORECAST_SOURCES` registers `replay` (I1 already sets `SB_FORECAST_SOURCE=replay` on `job-refresh`). The WhatsApp/SMS payload inspector is gated by `SB_ENABLE_WHATSAPP_ADAPTER` (rejected with `SB_ENV=prod`).
- Risk: ADOSH TWL zones (with the decided bias margin, ADR 0006), the 4-level probability overlay (Green/Amber/Orange/Red) mapped explicitly to the 3 zones, NIOSH RAL/REL with clothing adjustments, acclimatisation state machine (NIOSH 20%/day new, 50/60/80/100 experienced; ADOSH 5-7 day allowance and >14 days away = unacclimatised), policy engine with every action traced to a CoP clause or Table 1 row, hypothesis property tests ("fallback never less protective than the ban").
- Alert-burden comparison on real 2024-2026 weather: ours vs "WBGT ≥ 32" vs ban-only (ban window as dated configuration; exempt work categories listed).
- **Planner (ADR 0011 v2, Proposed 2026-11-11; supersedes the earlier CP-SAT-first line):** MUST on 16 Nov = rule-based ADOSH work/rest + Art. 18 break planner for a given shift and the day-ahead forecast (cycles across hour boundaries, graded acclimatisation, lone-work, stop-work) plus an **independent validator** and the planner back-test (`planner_scoreboard.json`: truth violation minutes, naive vs ban-only vs rule plan); invariants (no added minutes, sign-off never gates alerts or stops, employer scoping); pay-impact display only. Details: `2026-11-11-b3-planner-design-notes.md` (v2). k-suppression splits into `k_health` (≥ 10) and `k_exposure` (≥ 5).
